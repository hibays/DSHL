# 浏览器 pid 捕获预算跨托盘周期重置

- 日期：2026-08-23
- 状态：implemented
- 类别：bug-fix

## 背景

浏览器模式的关闭检测与几何采样都依赖 `BROWSER_PID`。捕获有 8 次 ×2s 的重试
上限，但计数器与放弃旗标是 run_loop 的**局部变量**——一旦放弃，后续所有
「关浏览器 → 托盘恢复」周期都拿不到 pid：

- 关闭检测退化为仅靠 is_shown 闩锁；
- 几何采样停摆（browser 模式的窗口尺寸/位置不再持久化）；
- 表现为「托盘恢复只有第一次有效，之后没反应」的家族性症状之一。

## 决策

把捕获预算提为共享状态原子
（`state::BROWSER_CAPTURE_ATTEMPTS` / `BROWSER_CAPTURE_GIVEN_UP`），并在
`restore_from_tray` 成功重建窗口时清零——**每次托盘恢复都是一轮全新的捕获
机会**，与「尊重既有环境」不冲突（探测不到时仍安静放弃，只是每个周期重新
给机会）。

## 否决的备选

- 完全去掉重试上限：会回到无限日志自旋的老问题。
- 由 restore 直接同步探测一次：show 返回瞬间浏览器可能尚未创建窗口，
  同步探测大概率落空。

## 验证

- 真机场景：浏览器模式连续两次「关窗 → 托盘恢复」，第二次起日志应出现
  browser supervisor 活跃与几何采样行；
- 单元层无 GUI 可测，依赖真机验证（仓库主人执行）。
