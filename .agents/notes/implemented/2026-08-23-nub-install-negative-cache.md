# nub 安装失败负缓存（会话级）

- 日期：2026-08-23
- 状态：implemented
- 类别：process

## 背景

`pm = "nub"`（新默认）下，每次启动 runtime_env 都会确保 nub 存在；当安装
注定失败时（无 npm、registry 不可达），旧逻辑**每次启动都重试完整安装流程**，
npm 的连接/重试超时叠加出数秒级的可感知启动延迟——且失败是确定性的，重试
永远失败。

## 决策

`install/nub.rs` 增加会话级负缓存 `INSTALL_FAILED: AtomicBool`：

- 安装失败 → 置位；后续启动直接走空返回（零网络、零进程）。
- 成功安装会写 marker 并隐式清位；下次正常走缓存快路径。
- 仅会话内生效：重启进程即重置，给环境修复后的用户新的机会。

## 网络策略（同批入档的全仓约定）

| 调用类别 | 超时 | 正确性保障 |
|---|---|---|
| 安装 / 下载类（bun/nub 本体、Node 发行版、deps 安装） | **无界** | curl `-C -` 断点续传 + 工具自身重试；中断后从已下载字节继续 |
| 探测 / 校验类（--version、registry 查询、全局程序校验） | 一律有界（probe 30s / registry 查询 3s / 全局校验 15s） | 失败降级为"无版本"，不得从崩溃输出挖版本号 |

## 验证

- 编译 + workspace 测试全绿；
- 真机验证点：断网启动应秒级进入「回退内置链」日志而非长时间卡在
  install nub。
